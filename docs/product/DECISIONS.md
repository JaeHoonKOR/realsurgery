# 사용자 결정 대기

- 규칙: 5건 이하로 유지한다. 세션은 결정이 필요한 일을 여기 올리고, 결정 전에는 그 일을 건너뛰고 다음 기능으로 간다.
- 결정되면 줄을 지우고 결과를 해당 문서(BRIEF·CONTENT·features.json)에 반영한다. 지난 결정 기록은 git log로 본다.
- 형식: `- [ ] D-n | 무엇을 정하나 | 왜 필요한가 | 정하기 전 기본값`

- [ ] D-1 | 서비스 컨셉 (무료·이용자 수·바이럴은 확정, 대상과 공유 장치는 미정) | 콘텐츠·화면 정의의 출발점 | 결정 전에는 기능 개발을 시작하지 않는다 (`/define brief`에서 정함)
- [ ] D-2 | 도메인 구매 (비용 발생) | 검색 색인에 2~4주가 걸려 가장 느린 병목. 네이버 서치어드바이저 등록 전제 | `jaehoonkor.github.io/realsurgery` 하위 경로로 배포
- [ ] D-3 | 계정·키 1회 세션: Supabase, GTM/GA4, 메타, Resend, Gemini (절차 `docs/archive/SETUP-HUMAN.md`) | 상담 접수 저장·트래킹 실측·일러스트 생성 | 키 없는 서비스는 mock 동작
- [ ] D-4 | 공개 전 변호사 1회 검토 (비용 발생): 사이트의 의료광고 해당 여부, 통신판매업 신고, 동의 문구 | 실서비스 공개의 법적 전제 | 리드 수집 화면은 공개 배포에서 끄고 정보 콘텐츠만 공개
- [ ] D-5 | 사업자 정보와 운영 시간 (푸터 표시) | 실서비스 표시 의무 | "사업자 등록 절차를 마친 뒤 이곳에 게시합니다." 표시
