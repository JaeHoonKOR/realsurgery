## 대상
강남언니 웹(gangnamunni.com), 바비톡 웹(babitalk.com), 여신티켓(yeoshin.co.kr), RealSelf(realself.com 시술 페이지), Zocdoc(zocdoc.com 의사 상세). 각각 메인·시술 상세·병원/의사 상세·상담/예약 폼 4화면.

## ACT
1. Playwright로 각 화면을 375×812·1280×800에서 연다. 로그인 벽이면 공개 범위까지만.
2. 화면마다 측정해 표로:
   - 첫 스크롤에 보이는 것: 가치 제안 문장, 카드 수, 신뢰 수치, CTA 수·위치
   - 밀도: 375×667 구간별 비텍스트 요소 수(이미지·SVG·아이콘 카드), 평균·최소
   - 인터랙션 목록: 호버·아코디언·탭·스티키·진행 표시·애니메이션
   - 데이터 시각화 방식: 가격·후기·거리·회복을 어떻게 보여주는지
   - 상담/예약 폼: 단계 수, 필드 수, 진행 표시, 완료 화면 내용
   - 로딩·빈·에러 상태 처리
   - 약점: 느린 LCP, 앱 유도 팝업, 광고 과다, 접근성 문제 (우리가 앞설 지점)
3. 스크린샷은 `reports/benchmark/<service>-<screen>-<w>.png` (참고용, 재배포 금지).
4. `docs/BENCHMARK.md` 작성:
   - 서비스×화면 측정표
   - **"우리가 넘어야 할 항목" 체크리스트** — 각 항목에 벤치마크 최고값과 우리 목표값(≥ 최고값)
   - **"우리가 앞서는 지점"** — 웹 우선, 출처 투명성, 공개 인사이트, 구조화 데이터 노출, 속도
   - 화면별 "반드시 있어야 할 요소" 목록 (QUALITY 2절·레이아웃 명세의 입력)
