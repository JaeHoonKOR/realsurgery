## 가정
- 가정: "동등 JSX 표현"은 `href={"#x"}`, ``href={`#x`}``, 객체 리터럴 `href: "#x"`/`to: "#x"`로 해석한다. SVG `url(#id)`는 예외로 두지 않는다(리뷰 지시가 "href/id/to 뒤만"이며, id가 hex 문자만으로 된 경우에만 걸리므로 id 이름을 바꾸면 된다).
- 가정: 인라인 style은 숫자 0과 CSS 변수(`var(--…)`)만 허용, 그 외 숫자 리터럴·`\d+(px|rem|em)` 문자열은 위반.
- 가정: 객체 리터럴 예외는 `href:`만. `to:`는 그라디언트 `{ from: "#fff", to: "#000" }` 색과 겹쳐 예외에서 뺐다(JSX 속성 `to="#…"`는 지시대로 예외).

## 리스크 3줄
1. 워크플로는 로컬 YAML 파싱만 확인했다. `pages: read`만으로 `configure-pages@v5`가 동작하는지, deploy job 권한 분리가 실제로 배포되는지는 첫 PR/main push의 Actions 실행에서야 확인된다(실패 시 build job에 `pages: read` 범위를 재점검).
2. check-tokens는 줄 단위 정규식이라 `style={variable}`·스프레드·`.svg` 파일(`app/icon.svg`는 파비콘이라 리터럴 색이 불가피)·여러 줄로 나뉜 속성 값은 검사하지 않는다. JSX 속성 `id="#…"`/`to="#…"`는 지시대로 예외라 SVG `<animate to="#fff">` 형태는 통과한다.
3. 인라인 style 규칙이 새로 생겨 T-100b 이후 화면에서 `style={{ zIndex: 10 }}`·`opacity: 0.5` 같은 값도 lint 실패가 된다 — 의도된 엄격함이지만 정당한 동적 값은 CSS 변수(`var(--…)`)나 토큰 클래스로 우회해야 한다.
