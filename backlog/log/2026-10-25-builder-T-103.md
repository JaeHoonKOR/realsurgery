## 가정 (무인 모드, 가장 단순한 해석)
- 가정: **MDX 파일 = 시술 콘텐츠 원본.** `content/procedures/<id>.mdx`(프런트매터 + 본문). DB `procedures.content_mdx` 에는 파일 전체를 넣고, 컬럼 값(name·가격 등)은 프런트매터에서 만든다. `data/seed/procedures.json` 은 id·view_count 만. Supabase 모드에서도 저장소 MDX 가 DB 행보다 우선하고, DB 에만 있는 시술은 content_mdx 를 같은 규칙으로 검사한다. 본문 없는 시술은 빌드 실패(빈 페이지 배포 금지).
- 가정: 파일 이름은 한글 slug 가 아닌 ASCII id(`double-eyelid.mdx`) — CLAUDE.md 파일명 규칙이 pipelines/03 의 `<slug>.mdx` 보다 우선(spec-question T-011).
- 가정: "시드 데이터(10개)로 정적 생성" + "콘텐츠 lane 이 1편씩 추가" → 4절 본문 5섹션이 빈 페이지가 없도록 **시드 10편의 MDX 초안을 시드에 이미 있던 수치·FAQ·출처만으로 작성**했다. content lane(T-300~)은 같은 파일을 3개 이상 출처 재검증 후 교체·보강한다. 프런트매터 값은 기존 시드와 동일(가격·FAQ 변화 없음).

### LCP 조사 (게이트 2.0s)
- 첫 측정 P-03 LCP 2.117s(FAIL). LCP 요소 = 직답 문단. 실험: 문서 gzip 10.8KB → 1.954s, 본문만 뺀 16.8KB → 2.111s → **문서가 gzip 약 14KB(lantern TCP 초기 창)를 넘으면 한 왕복(≈150ms) 늦어지고 그 뒤 JS 가 밀린다**가 원인. 홈(7.8KB)은 1.95s.
- App Router 정적 HTML 은 화면 HTML 과 같은 내용을 RSC 페이로드(self.__next_f)로 한 번 더 인라인한다(P-03: DOM 9.6KB + 페이로드 11.2KB gzip). 콘텐츠가 길수록 커지므로 class 줄이기만으로는 지속 불가.
- 해결: `scripts/externalize-rsc.mjs`(next build 직후) — 인라인 RSC 조각을 같은 순서로 `<페이지>.rsc.js` 로 옮기고 원래 위치에 일반 `<script src>` 1개(빌드 ID 쿼리). 문서는 화면 HTML 만(쌍꺼풀 gzip 9.0KB). **defer 는 안 됨**: Next 는 readyState≠loading 이면 스트림을 닫아 경쟁 발생(e2e 에서 "Cannot enqueue… closed" 재현) → 파서 차단 script 로 바꿔 해결(home·P-03 e2e 4회 반복 172/172 통과).
- 함께 줄인 것: JSON-LD 중첩(@id URL 반복 제거)·선택 속성(description·citation·keywords) 제거, FAQ 꺾쇠·관련 카드 화살표·출처 아이콘 SVG 제거(CSS·문자), MDX 본문·FAQ·관련 카드 스타일을 부모 클래스(@apply 토큰 유틸리티)로.
- 실험 중 발견·수정: 느린 CPU(6x)에서 하단 고정 동의 배너가 반쯤 파싱된 채 그려졌다가 커지며 CLS 0.099(10회 중 1회; 병렬 e2e 홈 폰트 스윕에서도 1회 재현). 배너 마지막 자식 `[data-consent-end]` 가 파싱되기 전에는 `display:none`(`:has`) → 15회 측정 이동 0.

## 리스크 3줄
1. LCP 여유가 작다(P-03 1.966s / 홈 1.971s, 기준 2.0s). 나머지는 Next 기본 JS(약 100KB)라 페이지 쪽에서 더 줄일 곳이 거의 없다. 문서가 gzip 14KB 를 넘으면 다시 실패하므로 e2e 가 쌍꺼풀 문서 크기(≤14KB)를 검사한다 — content lane 이 본문을 크게 늘리면 이 테스트·LH 가 먼저 알린다.
2. `externalize-rsc` 는 Next 내부 형식(`self.__next_f` 부트스트랩, DOMContentLoaded 에 스트림 닫기)에 기댄다. 형식이 바뀌면 빌드가 실패하도록(부트스트랩 검사) 했고 하이드레이션은 e2e(이벤트·클라이언트 이동)로만 보증된다 — Next 업그레이드 때 재확인 필요.
3. MDX 초안 10편은 시드에 있던 수치·출처(기관 홈페이지 수준 URL)를 재배치한 것이라 출처 재검증·의료 자문 검토는 content lane(T-300~)·사람 몫. 쿠팡 파트너스·Supabase 키가 없어 추천템·DB 반영은 미검증(needs-key).
