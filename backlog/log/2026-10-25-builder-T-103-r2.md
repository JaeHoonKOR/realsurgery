## 반려 ① — rsc.js 로드 실패 시 빈 화면 → 해결(외부화 유지)
- 원인: 페이로드가 없으면 Next `app-index` 가 DOMContentLoaded 에 빈 스트림을 닫는다 → Flight "Connection closed." → React 루트 오류로 document 가 비워진다.
- 해결(`scripts/externalize-rsc.mjs`): Next 는 하이드레이션 전에 `appBootstrap → loadScriptsInSequence(self.__next_s, cb)` 를 거치고, 스트림 생성과 DOMContentLoaded 닫기를 맡는 `app-index` 는 그 cb 안에서야 require 된다(`next/dist/client/app-next.js`, `app-bootstrap.js`).
  - `<head>` 맨 앞(모든 스크립트보다 먼저, 빌드에서 위치 검사)의 인라인 GATE(142B)가 `self.__next_s` 를 "reduce 하면 페이로드 완료 Promise 를 돌려주는" 객체로 둔다.
  - 외부 파일 끝에 `self.__rs_rsc_ok=1`. `<script src>` 바로 뒤의 GUARD(287B)가 이 표시를 확인해 Promise 를 푼다. 표시가 없으면 `self.__next_f` 를 비우고 `?…&retry=1` 로 1회 재요청하며, 파일이 끝까지 실행된 경우에만 하이드레이션한다.
  - 재요청도 실패(abort·404·잘린 응답·HTML 응답)하면 app-index 가 실행되지 않아 정적 HTML 이 그대로 남는다(링크·`<details>` FAQ 는 JS 없이 동작).
- e2e(`tests/e2e/procedure.spec.ts` "RSC 페이로드 실패", 375·1280):
  - abort / 404: H1·본문 H2 5개·FAQ 답변 텍스트·body 2000자 이상이 유지되고 `<details>` 가 열린다.
  - 같은 두 경우에 JS 청크 실행(`window.next`)을 확인한 뒤에도 `self.__next_f` 가 undefined 다(= app-index 미실행). 재요청 URL 도 확인. pageerror·예상 외 콘솔 0.
  - 첫 요청만 abort → 재요청으로 하이드레이션된다(view_procedure 1회, 동의 저장 동작).
- 음성 대조: 빌드된 쌍꺼풀 HTML 에서 GATE 만 지우고 abort 테스트를 돌려 실패하는 것(app-index 실행됨)을 확인한 뒤 재빌드했다.
- 외부화를 유지했으므로 LCP 2.0s(QUALITY) vs 2.5s(screen-spec) spec-question 은 이번에 제기하지 않았다(리뷰 권고 R3 는 오케스트레이터 판단 사항으로 남김).
